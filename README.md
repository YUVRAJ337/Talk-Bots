## Problem Statement

> Build a chat app with two bots talking to each other. Seed the first message and let the conversation continue for a fixed number of iterations. The bots must be powered using the OpenAI SDK running a language model (either locally or via any free cloud API, e.g. Groq, OpenRouter, Gemini).

## Overview

`two_bots.py` is a command-line program in which two AI bots discuss a topic for a fixed number of replies. Each bot runs on a different provider, and both are called through the **OpenAI Python SDK** using the providers' OpenAI-compatible endpoints.

| Bot | Provider | Model |
|---|---|---|
| **Ava** | Google Gemini | `gemini-3.5-flash-lite` |
| **Ben** | Groq | `openai/gpt-oss-20b` |

## How It Works

```
Seed (Ava) ──► Ben (Groq) ──► Ava (Gemini) ──► Ben (Groq) ──► ... ──► stop after N replies
```

- Ava opens the conversation with the seed message. This message is not generated by a model, so it uses no API request.
- Ben replies first, then the bots alternate: Ben, Ava, Ben, Ava, and so on.
- Each bot has its own instructions (system prompt) and its own conversation history.
- Each bot sees the other bot's messages as the `user` role and its own messages as the `assistant` role. From each model's point of view, it is talking to a user.
- The transcript is saved to a Markdown file after every reply, so partial progress is kept if the run is interrupted.

With `--turns 10`, the program generates ten replies: five from Groq (Ben) and five from Gemini (Ava).

## Requirements

- Python 3
- A Gemini API key
- A Groq API key
- The `openai` Python package

## Setup

Create and activate a virtual environment, then install the dependency.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install openai
```

On Windows PowerShell, activate the environment with:

```powershell
.venv\Scripts\Activate.ps1
```

### API keys

Create a key from each provider's console:

- Google AI Studio (Gemini)
- Groq Console

Set both keys in the terminal before running the program.

```bash
export GEMINI_API_KEY="your-gemini-key"
export GROQ_API_KEY="your-groq-key"
```

On Windows PowerShell:

```powershell
$env:GEMINI_API_KEY="your-gemini-key"
$env:GROQ_API_KEY="your-groq-key"
```

Keep API keys private. Do not paste them into the Python file, this README, or GitHub. Provider pricing and free-tier limits can change.

## Usage

Run with the defaults:

```bash
python two_bots.py
```

Run with a custom opening message and ten replies:

```bash
python two_bots.py --seed "Should cities invest more in public transport?" --turns 10
```

Save the transcript under a different filename:

```bash
python two_bots.py --seed "Should cities invest more in public transport?" --turns 10 --save transport-debate.md
```

### Options

| Option | Default | Meaning |
|---|---|---|
| `--seed` | built-in topic | Opening message from Ava |
| `--turns` | `10` | Number of bot replies after the seed |
| `--save` | `conversation.md` | Transcript filename |

## Design Choices

- **Two providers:** Running Ava on Gemini and Ben on Groq shows that the same SDK code works with different backends. Only the base URL, API key, and model name change.
- **Separate histories:** Each bot keeps its own message list, so each one keeps its own instructions and its own view of the conversation.
- **Fixed number of replies:** The loop runs exactly `--turns` times, so the conversation always ends.
- **Keys in environment variables:** Keys are never stored in the code or the repository.
- **Saving after each reply:** The transcript is written after every reply, so an API error late in a run does not lose the earlier turns.

## Limitations

- Free tiers have rate limits, and a long conversation may hit them. Free model names and limits can also change, so a model may need to be replaced later.
- The two bots use different models, so their writing style and quality differ. That is intended here, but it can make one bot seem more fluent than the other.
- The conversation has no stopping condition other than the turn count, so bots may start repeating each other in long runs.
- Each run starts fresh. Nothing is remembered between runs.
